# Farsh! — project instructions

Personalized hardcover children's books. Static templated HTML
pages + a small Node API for AI story text and illustrations. Real orders ship.

## Tech stack
- Node >= 18, CommonJS, Express 5 (`server.js`) — no framework, no build step
- Anthropic SDK (story text), Gemini REST (illustrations), Resend (order email)
- `@vercel/blob` for generated art in production; `uploads/generated/` locally
- Tests: `node --test`, no test framework or mocking library

## Build & run
- Dev/prod server: `npm start` (http://localhost:4000, `PORT` overrides)
- Tests: `npm test` — all of `test/*.test.js`
- No linter, no formatter, no typechecker configured

## Structure
```
server.js       Express app: static files + API routes + rate limiting
api/*.js        Vercel serverless twins — one per route, mirroring server.js
lib/            All real logic; both server.js and api/ import from here
test/           One *.test.js per lib/ module
*.dc.html       The site — dc-runtime templated pages (support.js is generated)
_ds/            Modernist design-system bundle (fonts, colors, base styles)
uploads/        Sample photography + locally generated art
docs/           Design notes; REVIEW-master.md is a prior audit
```

## Rules that matter here
- **Logic lives in `lib/`.** `server.js` and `api/*.js` are thin twins of each
  other. Change one route → change both, and the shared lib once.
- **Never trust the client.** `lib/placeOrder.js` re-validates everything the
  builder UI checks; `lib/clientIp.js` reads the forwarded chain from the right
  and only behind a real proxy (leftmost XFF is attacker-supplied).
- **Route registration order in `server.js` is load-bearing.** The 8mb `artJson`
  routes must stay registered before the app-wide 256kb `express.json()`.
- **Bound anything that reaches a paid model.** See `LIMITS` in
  `lib/generateBook.js` — rate limits cap request count, not prompt cost.
- **Degrade to the stock content, never to a lie.** Missing `ANTHROPIC_API_KEY`
  or `GEMINI_API_KEY` → sample story / typographic art. But a failed order must
  fail loudly: the email *is* the order record, so `placeOrder` resolves only
  after Resend accepts it.
- **Customer-facing `message` never carries setup instructions or internals.**
  Operator detail goes to `console.error`; the README says to look there.
- `support.js` is generated by dc-runtime — do not hand-edit.

## Conventions
- Files: camelCase in `lib/`, kebab-case in `api/`, `*.test.js` beside nothing
  (all in `test/`)
- Errors: throw `Error` with a `.code` for expected failures; HTTP layer maps
  code → status + safe message
- Async/await throughout; no callbacks
- Comments explain *why*, often at length. Match that — terse code with a
  paragraph of reasoning above it is the house style.
- Commits: sentence-case imperative describing the user-visible effect
  ("Refuse to print a book nobody has put a name in"), not the mechanism.

## Child-only for now
Only the child book is sold. `lib/audiences.js` is the single allow-list:
`placeOrder`, every generation route, and the pages all defer to it. The
couple/family prompts, fields and page themes are kept dormant in place so
widening the catalogue later is a one-line change there plus un-hiding the UI.

## Not built yet
Payment processing (Checkout collects details and emails the order; nothing is
charged). Arabic/RTL UI, despite MENA being the primary market.
